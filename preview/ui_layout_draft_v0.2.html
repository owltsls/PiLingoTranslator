一、已选定：方案 A · 100% 复制 HTML 设计稿

界面层改为「原生窗口 + 嵌入式 WebView 直接渲染 HTML/CSS」，本页即界面本体，视觉一致度 100%。

为什么只有它能做到 100%：折角标签靠「负偏移 + 父级 overflow:hidden + 圆角裁剪」、提示圆点靠 ::before 伪元素、按钮靠 transition 过渡、阴影靠 box-shadow 模糊——这些本来就是 CSS 能力，交给浏览器渲染即可原样呈现。Qt 样式表不支持伪元素 / 父级裁剪子控件 / CSS 过渡，圆角遮罩还与阴影效果互斥，字体渲染也不同，所以原生路线最多到 90–95%。

离线约束不变：WebView 只加载本地打包的 HTML/CSS/JS，不监听任何端口、不启动 HTTP 服务、不联网；离线守卫仍阻断所有出站连接，选中文本 / 剪贴板 / 截图 / 手动输入全部不出本机。当初 v3.0 的「去 Web 化」针对的是 V0.3 的 localhost + 浏览器 + HTTP 路由 架构，与本地嵌入式渲染不是一回事。

落地项做法影响
窗口外壳Qt 继续负责无边框、圆角、置顶、托盘、全局热键、截图框选；每个窗体放一个 WebView 承载对应 HTML 片段窗口行为与现在一致，用户无感

六、附带诊断：WPS 打开时悬浮窗不触发

根因已定位：默认「选中即译」模式下，剪贴板兜底通道压根没有注册，取词只靠 UI Automation 一条路。

① should_register_hooks() 中 clipboard 仅在触发模式为 copy / both 时注册，而默认是 select；decide_capture() 又会直接拒绝 select 模式下的剪贴板来源。于是只剩 UIA 一条通道。

② WPS 的文字编辑区是自绘控件，通常不实现 UI Automation 的 TextPattern，读不到选中文本 → 静默返回空；换到浏览器 / 记事本等标准控件又能读到 → 这正好解释「开着 WPS 不行、关掉就能用」以及「偶尔能用」。

③ 还有一处放大了问题：capture_selection() 把「不支持取词」的异常吞成了返回值，不会抛出，因此 _on_uia_tick() 里的「连续失败 30 次自动提示改用热键」实际上永远触发不了。用户遇到 WPS 时是完全静默、没有任何提示，按 Ctrl+C 也因为通道未注册而无效。

修复方向（等你确认布局后一并落地）：默认触发模式改为「两者皆可」并始终注册剪贴板作为兜底；UIA 连续失败时给一次轻提示「该程序不支持直接取词，请选中后按 Ctrl+C」；对 WPS 这类程序自动引导到已有的专属捕获热键；另外补一个「同权限运行」检测（WPS 若以管理员运行，跨完整性级别 UIA 也会失效）。
